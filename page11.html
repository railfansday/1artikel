InfoQ Homepage News Varlock Releases Bumpy: A File-Based Versioning Alternative to Changesets

Nov 07, 2026 2 min read

Bumpy, a modern monorepo-friendly version management and changelog tool from the team behind Varlock, has been gaining traction as a self-described successor to changesets. First unveiled in April 2026 via a Show HN post from creator Theo Ephraim, the project now ships under the @varlock/bumpy package and claims to address more than 120 open issues from its predecessor.

Bumpy follows the familiar changesets workflow. Contributors drop a small markdown "bump file" into .bumpy/ that declares which packages should be released, at what level, with a changelog description. The files are reviewable in the PR diff, consolidated into a release PR by CI, and consumed when that PR merges. An example looks like this:

Where the two tools diverge is beneath that surface. Bumpy ships with full support for workspace: and catalog: protocols across npm, pnpm, Yarn and Bun, per-package custom publish commands for VS Code extensions, Docker images or JSR targets, and a configurable three-phase dependency propagation algorithm that lets teams decide how peer dep bumps cascade through their graph. The CI story is leaner too, with two commands, bumpy ci check and bumpy ci release, running directly in a standard GitHub Actions workflow with no GitHub App to install or separate action repo to trust.

Version 1.14 added branch-based prerelease channels where prerelease versions are derived at publish time and never committed to git. The design targets complaints documented in the changesets own prerelease docs, which describe their pre mode as "very complicated" with states that are "very hard to fix". Another differentiator is AI integration. Bumpy ships an agent skill that teaches LLMs how to inspect git changes, identify affected packages and generate bump files via bumpy add. It installs through the Vercel Labs skills CLI, the GitHub CLI, or as a Claude Code plugin.

Getting started is a single install and an init that migrates existing changesets projects automatically:

A Show HN thread was candid that the project "was coded using AI, but carefully", and the team notes it is already being used to release Varlock alongside 25+ related libraries and plugins. In a separate thread on polyglot monorepos, bumpy was mentioned as a tool that "fixes a few things with changesets around custom publishing". Teams evaluating migration have opened issues flagging gaps such as Yarn 4.10 catalog detection.

Competition tightened with the changesets v3 release in August 2026, which closed many of the long-standing issues bumpy originally targeted. Bumpy's own differences doc now compares against v3 and credits it as "a substantial cleanup", while pointing out remaining gaps around configurable propagation, catalogs, custom publish targets and prerelease workflows. Relative to semantic-release, bumpy keeps the file-based model but adds a bumpy generate command that can produce bump files from branch commits when teams want to bridge both styles.

Bumpy is MIT-licensed, built in TypeScript, and available via the @varlock/bumpy package on npm, with the full source and documentation on GitHub.

InfoQ Homepage News Open Source pg_vectorsearch Brings More Scalable Vector Search to PostgreSQL

Nov 07, 2026 3 min read

Tiger Data has released pg_vectorsearch, an open source PostgreSQL extension for vector similarity search, currently in alpha. Its PRISM index uses data partitioning and compression instead of the graph-based approach used by pgvector’s HNSW index, reducing memory requirements and index build times.

According to the authors, pg_vectorsearch enables faster, more memory-efficient vector search directly in PostgreSQL, reducing the infrastructure required to handle large vector datasets. The extension supports existing pgvector columns, allowing applications to perform vector search without a separate database. To use the new capabilities, developers must install the extension and create a PRISM index on the vector column:

In Tiger Data’s own benchmarks using 100 million vectors, PRISM built an index in 1 hour and 40 minutes on a machine with 128 GB of memory, while HNSW (Hierarchical Navigable Small World) took 42 hours on a machine with 512 GB of memory. Formerly known as Timescale, Tiger Data is the company behind TimescaleDB, the open source PostgreSQL extension for time-series data and real-time analytics.

Erik Nordström, senior staff engineer at Tiger Data, Matvey Arye, principal engineer at Tiger Data, and Noah Hein, staff product marketing manager at Tiger Data, write:

PRISM brings a partition-based approach to PostgreSQL, similar to the approach used by newer dedicated vector search systems. Instead of connecting every vector to its neighbors in a graph, PRISM groups similar vectors into partitions and stores them as a list in a compressed format that is densely packed into database pages.

While HNSW is an approximate nearest-neighbor algorithm that quickly finds vectors similar to a query in large datasets, PRISM narrows searches to relevant partitions and scans compressed vectors sequentially. This reduces index size and avoids costly random memory or disk access, enabling faster vector search with less RAM directly in PostgreSQL.

Michael Freedman, cofounder and CTO of Tiger Data, published an article describing the architecture of the PRISM vector index. The index in pg_vectorsearch combines hierarchical clustering to narrow the search space, compressed vectors for efficient sequential scanning, and RaBitQ quantization to reduce expensive distance calculations. It duplicates vectors near partition boundaries to improve recall and relies on PostgreSQL’s native storage, logging, and concurrency mechanisms.

Incremental rebalancing is not yet fully implemented, so frequent data changes may require rebuilding the index to maintain search efficiency. Freedman explains:

The harder problem is maintaining the clustering as the dataset changes. Centroids don't automatically move when new vectors arrive, and posting lists gradually lose their original physical locality. We currently support limited on-demand splitting of oversized posting lists for flat indexes, but the more general rebalancing operations, including merging and reassignment, are not implemented yet.

In a popular Hacker News thread, the overall reaction is one of technical interest but caution. Practitioners see potential in faster vector search with lower memory requirements inside PostgreSQL, but raise questions about independent benchmark validation, whether pg_vectorsearch could replace pgvectorscale, and the lack of support for filtered searches. Hermon Hagos comments:

Vector search just got cheaper (...) For those of us building RAG apps on one database and a tight budget, that matters. Fast semantic search without spinning up a separate vector store or a bigger server is real money saved. It is still alpha, so do not ship it to clients yet, but this is one to watch closely.

Although not independently validated, Tiger Data’s benchmarks use an open source tool, measure recall@10 against exact search results, and compare both indexes under the same PostgreSQL configuration and instance types, using pgvector’s 16-bit halfvec for HNSW.

The new vector extension requires PostgreSQL 18 or later and currently supports vectors with up to 1968 dimensions. Filtered vector searches combining WHERE and ORDER BY are not supported until general availability. The project's code is available on GitHub. Tiger Data plans to move its existing pgvectorscale extension into maintenance mode.

InfoQ Homepage News How Grab Improved Mobile App Stability by Safely Handling Surge in AI-Generated Code Changes

Nov 07, 2026 2 min read

The growing adoption of AI coding assistants has accelerated development and increased the volume of code changes per release, bringing more opportunities for defects and crashes, says Grab. To address these challenges, they implemented a layered defense strategy to prevent, detect, and contain crashes throughout the development and release lifecycle.

Grab observes that "AI is speeding up how fast code is written; the layered defense is what makes that speed safe":

At [Grab's] scale, crashes leaking into production are an ongoing risk. A high volume of merge requests lands every week across many product teams, many shipping features behind flags that are switched on independently of releases. Any one of those changes can introduce a crash.

Beyond degrading the user's experience, a mobile app's crash reduces crash-free session rates and, as a consequence, the app's Google Play ranking. It also has an increased cost because not all users enable automatic updates, meaning that "a mobile crash that ships stays on users' devices" for longer. Furthermore, not all crashes come with clean, symbolicated stack trace, which means that "finding the cause means cross-referencing release timelines, flag rollouts, and session metadata".

Grab's layered defense follows a shift-left strategy aimed at catching crashes as early as possible through a series of safeguards along the development cycle phases: pre-merge through pre-production, release control, and post-release response.

During the pre-merge to pre-production phase, the goal is prevention, which Grab describes as its "primary line of defense". To achieve this, Grab engineers use static code analyzers such as Android Lint and SwiftLint to catch issues before code even merges via platform-specific, community-based, and custom lint rules; automated and manual testing, including unit tests, UI tests, and quality assurance (QA) checks; and Grab Early Access (GEA), a pre-production gate where early builds are distributed to internal users and actively monitored for crashes:

A crash that only a handful of internal users see in GEA would, at production scale, translate into a substantial spike in the crash rate, extra support load, and potentially a hotfix. Catching these crashes before they ever reach production users makes GEA one of our most important stability gates.

During the release phase, Grab uses staged rollout and feature flags to control production exposure to crashes. Staged rollout enables a new app version to reach only a small percentage of users initially, so engineers can monitor its crashes and possibly pause the rollout if an abnormal crash rate is detected. Features flags, in turn, allow teams to activate features gradually while monitoring their impact on crash rates. If a feature causes crash rates to exceed predefined thresholds, it be disabled immediately without requiring a new release.

During the post-release phase, Grab focuses on rapid incident response using mechanisms to detect, investigate, and contain production crashes. These include real-time crash monitoring using Firebase Crashlytics and BigQuery to identify anomalies as soon as a build goes live; automated triage and enriched diagnostics to aggregate crash metadata and stack traces, helping teams to map crashes to specific PRs; and feedback loops and post-mortem analysis to extend lint rules and test coverage.

There is much more to Grab's layered defense approach than can be covered here. Be sure to read the full article for all the details.

How to keep the same character across AI video clips with reference images (Kling 3.0 Omni, MiniMax H3, Wan, Seedance)

📅 2026-11-07  |  Read Source →

Posted on Nov 7 • Edited on Nov 7 • Fully Autonomous

The most common complaint about AI video is not quality. It is that clip two shows a different person from clip one. You describe "a woman with a copper-red bob and an olive jacket", and the model draws a new woman who fits that description every time you press Generate.

The fix that works is reference images: you show the model the same few photos of your character on every clip, and you stop describing her in words. This tutorial walks through how to do that, which photos to pick, how to write the prompt, and how the main reference models differ: Kling 3.0 Omni, MiniMax H3 (Hailuo), Wan 3.0 and Seedance 2.5. Every image below is a frame from a real, unedited clip we made in RefVid, the tool I work on.

Our test character is Mia. She is invented, not a real person, which matters later (some models refuse real-looking faces, and you should only ever use photos of people who agreed to it).

She has four reference images, and the set is the whole trick:

Reference 1 of 4: the front view. The sharpest, most evenly lit photo goes first.

Reference 3 of 4: the profile. Without it, a model has to guess her nose and ear when she turns.

Rules that held up across every model we tried:

Once the photos are attached, the prompt should only say where she is, what she does and what the camera does. Do not repeat her hair colour or her jacket. When the words and the photos disagree even slightly, the model blends them, and the blend is the drift you were trying to avoid.

Here is the prompt for the first clip, word for word:

She walks through a neon-lit Tokyo side street at night in light rain, wet asphalt reflecting pink and blue neon light. The camera tracks alongside her at shoulder height in a smooth lateral dolly as she walks.

Kling 3.0 Omni, 5 seconds, from the four photos. Not edited.

Then the same four photos with completely different scenes:

Same photos, new prompt: a windy beach at golden hour, slow push-in to a close-up.

Same photos: a Scandinavian kitchen in morning light, pouring coffee, then smiling at the camera.

Same photos: a misty pine trail, turning back toward the camera.

Four scenes, four lighting setups, one face. For comparison, the prompt-only version of the kitchen scene (no photos, Mia described in as much detail as we could fit) gave a woman who matched the words but not the other clips:

Words only, no reference images. Close, but not Mia.

All of the Mia clips above ran on Kling 3.0 Omni, which takes up to 10 reference images and makes 3 to 15 seconds. If you want to try it without the Kling app or an API key, our Kling 3.0 Omni free online page runs a first 5-second clip on it for free.

Reference images are not a Kling feature; most current video models have a reference mode. The useful part is that the same saved photos work on all of them, so you can pick a model per shot and the character stays put. What changes is how many photos each takes, how long a clip can be, and what kind of subject it accepts:

A new account's free credits cover one short first clip from your photos on several of these: MiniMax H3 (5 seconds at 768p, with sound), Wan 3.0 (4 seconds at 720p) and Vidu Q4, another reference model that takes 1 to 10 photos.

Hailuo's original subject reference model, S2V-01, read a single face photo. MiniMax H3 reads several. We sent it the same four Mia photos:

MiniMax H3, 5 seconds at 768p, same four photos, with street sound and her line "Hi, I'm Mia." Back in 33 seconds.

The differences between S2V-01 and H3 are laid out in our Hailuo subject reference guide.

Most Wan reference-to-video tutorials are ComfyUI workflows written for Wan 2.6 or 2.7. Wan 3.0 takes up to 10 reference images and runs up to 30 seconds in one pass, which is the easiest way to keep a character through a long continuous action instead of stitching 5-second clips. Write the actions in order, one per sentence, so the model knows the sequence. More in Wan reference to video online.

Seedance 2.5 refuses photos of real-looking people before the clip runs. For a product, a pet or an illustrated character it holds detail very well. Here is AERO 1, an invented running shoe, from three product photos:

Seedance 2.5, 5 seconds at 720p, from three photos. The knit upper, heel tab and white sole match the photos.

For an illustrated character, a reference sheet that shows it from several sides works as one of the photos. Details in Seedance reference to video.

If you try this and a model still drifts on your character, tell me in the comments which model and how many photos you used. That is usually where the answer is.

Schlägt semantische Code-Suche grep wirklich in einem echten Repository?

📅 2026-11-07  |  Read Source →

Der Pitch fürs Einbetten einer Codebasis ist immer dieselbe Demo: Man fragt „Wo sperren wir Nutzer aus?“, grep findet nichts, weil der Code das Cooldown nennt, und die Vektorsuche landet in der richtigen Funktion. Eine gute Demo. Die Frage ist, wie oft das bei Code funktioniert, den niemand für die Demo ausgesucht hat.

Hier also eine Messung an einem Repository, das die meisten Python-Entwickler irgendwann gelesen haben: psf/requests im Tag v2.32.3, mit zehn Fragen, bei denen grep nach der naheliegenden Formulierung null Zeilen liefert. Die Pipeline kopiert die, die die osFoundry-Desktop-App für ihren Index lokaler Ordner benutzt (Chunking-Regeln aus folder_index.rs, hybrides Ranking aus folder_search.rs), in unter 200 Zeilen Python nachgebaut und auf einem Mac M1 mit 8 GB ausgeführt, nur CPU. Die kurze Antwort: Embeddings allein fanden den richtigen Chunk bei 4 von 10 Fragen unter den Top 5. Ein schlichtes Keyword-Ranking derselben Frage fand 6. Beide zusammen fanden 7 in den Top 10, und 9, sobald Tests und Doku nicht mehr mit dem Quellcode konkurrierten.

Trillion-Parameter RL Weight Syncs Drop From 87 Minutes to 150 Seconds

📅 2026-11-07  |  Read Source →

Authors: Songlin Jiang, Zhiyu Li, Terry Kong, Yu Yao, Youngeun Kwon, Bernard Nguyen, Ashwath Aithal, Mario Di Francesco (NVIDIA)

Abstract. Agentic reinforcement learning (RL) disaggregates training from rollout, so each policy update must reach the rollout clusters before the next batch. Transferring a full 1T checkpoint for such weight synchronization (refit) takes 87.5 min between two AWS regions. Measurements of BF16 training show that about 1% of weights change their stored values per step. Recent systems exploit this sparsity but fall short on placement, exactness, or efficiency: they reimplement placement rules, assemble full tensors, rebuild values arithmetically, or use a cross-cluster collective, and none fully recovers from mid-refit failures. We present NeMo-DCR (Delta-Compressed Refit), which sends only changes yet is bit-exact: receivers obtain the same parameter and buffer bits as a dense refit. For placement, fixed affine mappings project changes from training shards into the checkpoint’s canonical coordinates, residual conversion covers the other changes, and the serving runtime’s native loader places all changes in receiver storage. For exactness, compressible XOR masks carry affine changes whose projection and loader preserve stored bits, and overwrites carry the others. Receivers apply both in place, retries overwrite partial writes, and a joint commit binds the policy to the baseline for the next delta. For efficiency, object storage or a relay tree streams payloads during delta construction, without a cross-cluster collective. Even at 3% and 5% change rates, NeMo-DCR refits of 30B–1T models are 12–40× faster than a transport-only full-checkpoint reference. A 1T relay-tree refit at 3% takes 150 s instead of 87.5 min, making refits practical for cross-cluster agentic RL at trillion-parameter scale. Agentic reinforcement learning (RL) spends over 70% of its wall-clock time in rollout, so rollout is disaggregated from training and runs on serving clusters with suitable hardware and parallel layouts [6, 7]. Before the next rollout batch, a refit must deliver the updated policy to the receivers, the rollout ranks that generate responses with a serving runtime [15]. Disaggregation also lets rollout run on idle serving GPUs [6] or in other datacenters [41, 40], where every refit must cross a wide-area network.

A cross-cluster transfer of a 120B model’s 247.2 GB checkpoint through object storage takes 750 s, and at the 1T scale of models like Kimi K2 [14], such a transfer takes 87.5 min (Figure 1). Yet in the six models of Figure 2, only 0.6–1.2% of training-side source elements change their bfloat16 (BF16) values per step. We call this fraction the element change rate. With only 8 significant bits, BF16 rounds most optimizer updates away. Other reports give element change rates of 1.5–2.0% in Qwen3 RL [26] and average deltas of 1.98% of a 1,024 GiB checkpoint [5]. A full-checkpoint transfer thus spends 98–99% of its bytes on unchanged elements.

A refit that sends only the changed 1% faces three challenges: placement, exactness, and efficiency.

First, placement: sparse source changes do not tell receivers where or what to write. A training-shard location does not map directly to a receiver’s storage location: refitting may gather, split, or permute tensors between training and rollout layouts [26]. A change to a shared scale factor can also alter converted values even when other source values stay unchanged [23]. Some systems reimplement the serving runtime’s placement rules [6, 26], and others extract a delta after full-tensor assembly and conversion, which handles both problems but pays for both steps [11].

Second, exactness: a smaller transfer must still deliver the exact updated bits, because rollout–training mismatch is known to destabilize RL [28]. Arithmetic reconstruction can introduce floating-point rounding errors [26], while absolute overwrites avoid rounding [19] but resend unchanged bits within changed values. Failures also threaten exactness: applying updates in place avoids a separate receiver-side baseline copy, but an interrupted refit can leave a mixture of old and updated values that matches neither policy version. Because a delta applies only to the version it was computed from [19], recovery must complete the interrupted refit before rollout resumes and keep receivers aligned with the source baseline that the next refit compares against.

Third, efficiency: delivery must overlap the other refit stages without a cross-cluster collective. The next rollout batch waits for the complete update, so without overlap, delta construction and application can offset the transfer savings. A cross-cluster collective couples receiver membership to the training cluster and introduces timeouts upon failure [22]. Some deployments share weights only through object storage [3], and others have direct links between clusters [40], so delivery must support both.

Existing systems meet these challenges only in part: they either send every weight or lack exactness, native placement, decoupled delivery, or recovery, so none meets all five requirements in Table 1. We present NeMo-DCR, a system for bit-exact delta refit that meets all five: it sends only changes, yet every receiver obtains the same parameter and buffer bits as a dense refit that sends every weight. The key idea is to describe changes in canonical coordinates, the tensor names and indices of the Hugging Face checkpoint format that both training and serving already support. Fixed affine index mappings project changes directly into these coordinates and cover over 96% of the weight bytes in the mixture-of-experts (MoE) checkpoints. The serving runtime’s native loader then maps these coordinates to receiver storage, much as a page table maps virtual to physical addresses.

Training systems and serving runtimes store the same policy in different layouts. Training systems shard parameters, gradients, and optimizer state to fit into GPU memory while maximizing update throughput [21, 29]. Serving runtimes organize weights for inference and maintain request state such as a paged key-value (KV) cache [15]. RL systems that coordinate the training and rollout sides must bridge the two layouts [32, 10, 13]. The two sides choose their parallel degrees independently, so one training shard can overlap several rank-local slices on receivers, and one slice can combine parts of several shards (Figure 3).

Figure 3: Top: one tensor in the training, canonical, and rollout layouts. Bottom: BF16 values near 0.5, labeled by their stored bits in hexadecimal. Values in the shaded interval round to 0x3F01, and only an update crossing its boundary changes the stored bits.

Both layouts map to canonical tensors: the model’s tensors in the Hugging Face checkpoint’s naming and layout, independent of either cluster’s sharding. Let Wv denote the canonical tensors at version v, including versioned buffers. A receiver r does not store Wv directly. Its native loader Lr is the serving runtime’s own weight loader and may split, combine, skip, transpose, or cast tensors before writing rank-local storage Prv=Lr​(Wv). For example, vLLM fuses the query, key, and value projections and splits routed experts across ranks. Each sequence of such operations is a loader path, and we consider loader paths whose output elements each come from one canonical element.

A refit must bring each receiver to Prv+1=Lr​(Wv+1), the result of a dense refit. Dense collective refit and full-checkpoint transfer produce this result by sending every weight, and Table 1 lists them as approaches A and B. We call the update to version v+1 a transition, which may take several attempts. Each attempt updates the current receivers, called its required receivers.

How many values a refit must update depends on training: an update changes a stored BF16 value only when it crosses a rounding boundary (Figure 3), so larger learning rates and early training steps change more stored values. Yet even in the first five steps of Group Relative Policy Optimization (GRPO) [31], the six models in Figure 2 show only 0.6–1.2% average element change rates, counting each unique source element once. Appendix E details the setup, which follows an agentic software-engineering (SWE) RL recipe with a constant 10−6 learning rate.

To exploit this sparsity, a refit must meet five requirements that make placement (G3), exactness (G1 and G5), and efficiency (G2 and G4) concrete (Table 1). G1 Bit-exact: starting from receiver storage Prv, a delta refit must produce the same parameter and buffer bits as a dense refit. G2 Delta: transfer volume must scale with the emitted changed values, their locations, and payload metadata. G3 Native: the native loader must determine placement, with no model-specific placement rules in the refit system. G4 Decoupled: no collective may span the training and rollout clusters. G5 Recovery: receivers must suppress duplicate payloads, partial writes must be recoverable, and one authoritative commit record must bind each new policy version to its source baseline after every required receiver holds its new storage Prv+1. No existing system in Table 1 fully meets G5, and each fully meets at most two of the five requirements.

Other systems that ship policy weights to serving runtimes are limited in scalability or efficiency: they send full checkpoints, rebuild full weights from deltas, or support only unsharded runtimes. INTELLECT-2’s SHARDCAST relays checksummed full checkpoints in pipelined shards [27]. In Composer 2 and Fireworks, trainers upload per-step deltas to shared storage, from which inference clusters rebuild full weights [3, 5]. TRL’s delta sync likewise rebuilds full tensors from a CPU snapshot [12], and the slime framework applies XOR or overwrite deltas to a full local checkpoint and reloads it at every refit [33]. vLLM patches runtime parameters in place, but doesn’t support any parallelism [37].

Related techniques target training traffic, fine-tuning, file transfers, or storage rather than policy refits: gradient compression [17, 38], low-rank adaptation [9], delta file transfer and lossless weight compression [34, 8], and compression of fine-tuning deltas and checkpoints [18, 16, 39, 4].

Canonical coordinates split a refit into delta construction and receiver-side placement. Figure 4 numbers the seven steps: owners construct deltas, a transport delivers them, receivers apply them, and the coordinator, which drives each attempt, publishes the policy with a joint commit. The next four sections (§§ 4–7) explain these steps in detail and develop the four contributions in turn: projection and conversion, encoding, application and recovery, and delivery.

Figure 4: NeMo-DCR architecture and the numbered steps of a refit. The coordinator calls prepare to start an attempt and open_apply to let receivers apply payloads and then acknowledge (ACK).

Projection and conversion (❶–❷, §4). Shard owners compare their weights with the source baseline and directly project changes covered by affine mappings, which are fixed and convert each source element independently. The rest are residual: their canonical tensors must be constructed first (contribution 1).

Encoding (❸, §5). The codec encodes a change as an XOR entry when projection and the loader path preserve stored bits and no other write overlaps it, and as an overwrite entry otherwise (contribution 2). The first three steps together meet G1 and G2.

Application and recovery (❺–❼, §6). Each receiver validates and deduplicates payloads, then applies their XOR or overwrite entries in place through the native loader. Failed attempts are retried with overwrites. After every required receiver acknowledges, the coordinator’s joint commit binds the policy version to its source baseline (contribution 3). These steps together meet G1, G3, and G5.

Delivery (❹, §7). Object storage or the relay tree delivers the entries in payloads without a cross-cluster collective (G4). Streaming overlaps delivery with delta construction and, in synchronous RL, also with application (contribution 4).

Example. Suppose that a BF16 element changes its stored bits from 0x3F01 to 0x3F02 in a matrix sharded by rows in training and by columns in rollout. Its owner detects the change (❶), projects it to its canonical destination d (❷), and emits the XOR mask 0x0003 in a compressed payload (❸). The payload reaches every rollout node (❹), and each node’s receivers validate it (❺). Each receiver whose column slice holds d intercepts the loader’s final storage copy in order to XOR 0x0003 into 0x3F01 (❻). The joint commit publishes the updated policy, and the owner’s baseline becomes 0x3F02 (❼).

Implementation. NeMo-DCR is about 7K lines of Python. It builds on Megatron Bridge conversion [23] and the vLLM native loader [15].

In ❶–❷ of Figure 4, NeMo-DCR compares each training shard with its source baseline in place, on the shard owners: direct projection avoids full-tensor assembly and conversion for affine changes, and residual conversion covers the other changes.

The changes that an owner can directly project depend on the conversion tasks through which the Megatron Bridge library converts training shards to canonical tensors [23]. Affine tasks convert each source element independently and deterministically with the fixed affine index mappings of supported mapping classes, such as those for replicated and row- or column-split shards. Tasks for fused query/key/value (Q/K/V) source tensors and other tasks outside the supported mapping classes are residual and require constructing canonical tensors. Affine mappings cover 96.3% of the weight bytes in the Qwen3-30B-A3B checkpoint and 97.0% in the Nemotron-3-Ultra-550B-A55B checkpoint, both MoE models, as Appendix D details.

In ❶, only one owner compares each unique source element against the source baseline, because data-parallel training keeps its replicas bitwise identical. A stable name hash balances ownership across data-parallel ranks (Figure A.2) and keeps it fixed across the attempts of a transition.

It contains a task tracker for each conversion task, holding the version-v values of the task’s source shard, and a distributed residual baseline of canonical tensors for residual tasks. Because each unique source element has one owner, the trackers together hold one copy of the source weights. For task T, let STv+1 be the candidate shard, ATv its tracker, and JT its owned indices. In ❷, residual conversion covers residual tasks, which fall outside direct projection because they lack a supported mapping, can spread a source change across several outputs, or combine inputs from several owners. Examples include stacking, padding, tied weights, adapters, custom postprocessing, and quantization scales. For these tasks, NeMo-DCR constructs the affected canonical tensors and compares their bits with the committed residual baseline (Figure 5).

Change detection covers every input of a conversion because a change in a shared scale factor λ can alter many converted values even when the other source values stay unchanged. For example, a fixed conversion rule may multiply each source value by λ and cast the product. Owners set a flag when a residual task’s shard changes (Figure A.4). The delta omits outputs whose converted bits remain unchanged.

Both paths feed one changed set: the emitted destinations combine direct projections πT​(CT) and residual changes Du. Each emitted destination has a delta record with its updated value, and these records form the complete changed set \mathcal{E} that the codec encodes.

In ❸, the XOR/overwrite encoding keeps reconstruction exact, and XOR also improves compression. Delta records in canonical coordinates share one codec and one payload format: the affine/residual path decides how a record is built, and the XOR/overwrite encoding decides how it is applied.

Exact encoding rules out arithmetic reconstruction, which can fail to recover the updated stored values: for an old value α and an updated value β, rounding can make α+(β−α) differ from β, and such errors can accumulate across versions. NeMo-DCR instead sends either XOR masks of stored values or absolute overwrites. Both reproduce the new bits exactly: a mask flips only the bits that differ, and an overwrite replaces the whole stored value.

However, the mask yields the target bits only on a representation-preserving path, where the source projection QT and native loader preserve dtype and stored bits. In the shared-scale example of § 4.3, multiplication and casting change stored bits, so a source mask does not carry over to the converted values (Figure D.1). Comparison with the residual baseline finds such changes after conversion, and absolute overwrites carry the converted bits.

To exploit unchanged bits within changed values, the default mixed mode uses XOR entries (d,x) wherever an affine path is representation-preserving and no other write touches the same bytes. These conditions are decided in advance for each mapping class and loader path (Figure D.1). All other records become overwrite entries (d,o). In the two MoE checkpoints of § 4, most conversions are affine and preserve stored bits, so XOR covers more than 96% of the weight bytes, as Appendix D details.

XOR entries also compress well: small updates often leave high-order bits unchanged, so XOR masks contain many leading zeros. In the example of § 3, the XOR mask 0x0003 has 14 leading zero bits (Figure 5). Run-length and gap coding shrink location bytes, and level-1 zstd [2] then compresses both values and locations in each payload.

Yet XOR makes duplicate delivery unsafe: applying a mask twice restores the old bits (Figure 5), so receivers suppress duplicate payloads by their identifiers. For the same reason, retries repair partial writes with overwrites.

In ❺–❼, native-loader placement and overwrite recovery allow in-place refits from canonical coordinates without a receiver-side baseline copy. Reimplementing placement would duplicate the rules for fused Q/K/V, routed experts, slicing, padding, transposition, and tied weights. NeMo-DCR instead lets the native loader apply these rules, intercepts the loader’s final storage copies, and specifies loader conditions that guarantee dense-refit bits. Overwrite recovery repairs partial writes, and a joint commit keeps receiver storage and the source baseline in version alignment: each transition starts with every required receiver at the committed version.

Receivers apply payloads through the native loader one item at a time, where an item holds one owner’s entries for one tensor. After validating and deduplicating payloads (Figure B.2), each receiver scatters each item into a reusable host scratch buffer with the canonical tensor’s shape and dtype. Positions without an entry are inactive and hold a placeholder q (Figure 6, top). The loader resolves names and transforms the scratch, while a PyTorch dispatch hook updates only active positions at the loader’s final storage copies.

XOR path. Scratch holds the placeholder q=0 except for masks at changed positions, such as 0x0003 at d in the example. The intercepted copy XORs each mask into the matching resident element, and the copy’s input must share storage with scratch so the masks arrive unchanged. XOR with q=0 leaves inactive positions unchanged.

Overwrite path. Scratch holds overwrite values and a placeholder that must stay distinct from these values until the first intercepted copy into each destination view. At that copy, non-placeholder positions form the view’s boolean active mask of positions to update (Figure A.10). NaN is the default placeholder.

Receiver memory. Beyond resident weights, receivers keep only the scratch, staged payloads, and temporary buffers for active masks and optional post-apply checks of intercepted copies (Figures C.2 and A.12). A prewarm call reserves scratch for the largest canonical tensor and identifies the tensors that the native loader skips on each rank, such as routed experts held by other ranks.

Loader conditions. Exact delta application requires intercepting every storage write: the tensors the loader reports as loaded must match the intercepted copies, and an item without an intercepted copy requires an explicit native skip (Figure A.8). The loader must transform each canonical value independently and deterministically throughout the transition. XOR byte ranges must be disjoint from all other writes, and overlapping overwrites must yield the same bits as a dense refit. NeMo-DCR rejects unsupported loader paths in advance and fails any attempt whose copy breaks these conditions (Table A.2).

Under these conditions, a NeMo-DCR refit is bit-exact. Let Δv+1 encode \mathcal{E}, and let applyr apply Δv+1 at required receiver r, starting from its storage Prv.

Proof sketch. XOR reconstructs each new value from the resident version-v bits (Figure A.13, top). Overwrite supplies the value itself. Every changed destination has a record, and destinations without a record keep their version-v bits, which already match a dense refit because their canonical elements did not change. Overwrite retries extend Proposition 1 to transitions whose first attempt fails. Partial writes from a failed attempt leave receivers with a mixture of old and updated values. NeMo-DCR stops the failed attempt and waits until its writes can no longer take effect, then recomputes the complete changed set from the same candidate weights and unchanged Bv. Every record becomes an absolute overwrite, supplying the target bits regardless of which earlier writes completed (Figure A.14). The retry thus yields Lr​(Wv+1). Receiver membership changes take effect only between attempts, and new or restarted receivers restore the committed version through a dense refit before joining.

At the end of an attempt, the joint commit publishes the updated policy and binds it to its source baseline in a durable, versioned commit record that a control plane holds and changes only by compare-and-set. The coordinator commits after all required receivers have received every expected payload and finished application, device synchronization, and optional post-apply checks. A commit succeeds only if the commit record still equals the version-v record Kv. Owners then update the task trackers and residual baseline in place (Figure B.3). This update finishes before the transition ends or change detection resumes, so the next delta uses the committed baseline.

The commit record also makes coordinator failover safe: a new coordinator reads the same commit record before deciding whether to retry. Appendix B specifies the protocol as Algorithm B.2, with commit deadlines and the control-plane conditions for failover.

In ❹, pipelined delivery over object storage or a relay tree overlaps other refit stages without a cross-cluster collective. Owners emit the payloads, and both transports share the refit protocol of Appendix B.

Payload bytes scale with emitted values, locations, and metadata, but transport topology and retries determine how often payloads cross the cluster boundary. Let Vpayload be the total bytes in unique compressed payloads before replication to receivers, and Vcross the bytes crossing that boundary.

Object storage. This transport separates uploading from downloading (Figure 7, left). Owners upload each payload once and list it in a per-attempt manifest of expected payloads. Rollout nodes fetch every listed payload without a direct link. One stored copy in canonical coordinates serves every rollout node, but each download crosses the cluster boundary, so Vcross grows with the number of rollout nodes. A retry uploads the complete changed set again.

Relay tree. Where direct links exist, this transport streams each owner’s payloads to one root in the rollout cluster (Figure 7, right). The root forwards payloads through a balanced tree over local links, and each node’s receivers apply them. Without retransmission, each payload crosses the cluster boundary once per attempt, so Vcross≈Vpayload. Appendix B details both transports.

Overlap matters because payload volume scales with the changed set, whereas delta construction cost scales with model size: construction scans source shards and converts required residual tensors. To overlap delta construction and delivery, owners group whole tensors into chunks for comparison and pack the resulting records into buckets, each compressed into one payload (Figure 8, top). Buckets amortize the overhead of metadata, compression, and transfer.

A request gate shields requests from partially applied weights and closes at different times in synchronous and asynchronous RL. In synchronous RL, the coordinator closes it when the first attempt starts, and receivers apply payloads during delivery (Figure 8, bottom). In asynchronous RL, receivers stage the compressed delta in host memory while rollout keeps serving version v. After the last payload arrives, the coordinator closes the gate, and receivers apply the delta in place once current requests finish. The gate reopens when the transition ends.

Because only about 1% of BF16 values change per step, a delta refit can be much cheaper than a full-checkpoint transfer if it addresses placement, exactness, and efficiency, which NeMo-DCR does in canonical coordinates through four contributions. Direct projection avoids full-tensor assembly and conversion for affine changes, residual conversion covers the rest, and mixed XOR/overwrite encoding cuts Qwen3 payload bytes by 38–40% versus overwrites. Recoverable in-place refits match dense refits bitwise without a receiver-side baseline copy, and both transports follow dense NCCL’s mean reward and KL trajectories despite receiver kills. The source baseline stays in host memory and totals about one checkpoint across training ranks. Pipelined delivery without a cross-cluster collective overlaps delta construction with relay-tree transport, and the transport lower bound accounts for 77–94% of refit latency.

In the cross-cluster 3% and 5% stress cases for 30B–1T models, refits are 12–40× faster than the transport-only full-checkpoint reference, and the relay tree takes 150 s instead of 87.5 min at 1T and 3%. These results make per-update refits practical for cross-cluster agentic RL at trillion-parameter scale. NeMo-DCR is open source as part of NeMo RL [24].

Replication adds copies but not owners. The parallel layout identifies replica groups, which include the data-, context-, and expert-data-parallel replicas and the tensor-parallel copies of replicated parameters. Every training step keeps the copies within each replica group bitwise identical, so a stable name hash selects one owner among the copies of each shard (Figure A.2). Tied weights likewise have one owner and one task.

As in § 4.1, owners compare stored bit patterns, not floating-point values. Floating-point equality treats +0.0 and −0.0 as equal although their BF16 patterns 0x0000 and 0x8000 differ. On takeover, the new coordinator first stops and drains writes from the old attempt τold, then waits with read_commit until no commit of τold can change the record. If such a commit took effect, the new coordinator waits for the baseline update named by the record, cleans up, reopens the gate under τold, and returns 𝖼𝗈𝗇𝖿𝗅𝗂𝖼𝗍. If the record remains Kv, the new coordinator cleans up and retries in overwrite mode from the unchanged Kv, repairing any partial writes before its own commit replaces Kv. Owners hold their candidate shards and their baselines in memory, so they can finish the in-place baseline update after a coordinator failover. Because the update writes absolute values derived from the fixed Wv+1, an owner that reads the commit record again can safely repeat it. Failover therefore needs no durable record of which owners have finished.

The design meets all five requirements. § 6.2 and Appendix A establish G1, and the dense-refit comparisons of § 8.1 confirm it. For G2, the payload volumes of Tables 3 and 4 scale with the changed set. For G3, placement stays in the native loader with no model-specific logic, as §§ 6.1 and 8.1 describe. For G4, both transports deliver without a cross-cluster collective, as § 7 describes, and the latency runs of § 8.1 use them between clusters that share no InfiniBand or EFA route. Payload deduplication, overwrite recovery, and joint commit meet G5, as § 6.3 and Appendix B describe, and with receivers killed mid-refit, both transports follow dense NCCL’s mean reward and KL trajectories in Figure 9.

Approaches A and B fully meet G1, and approach D avoids arithmetic reconstruction but meets G1 only partly. NCCL-Reshard and checkpoint-engine send every weight rather than a delta, so they preserve the target bits [22, 20]. TensorHub copies its published buffers into the serving runtime’s registered tensors, which yields exact target bits because the published buffers hold the weights in the layout and dtype of the registered tensors [40]. PULSE’s Appendix H.6 proves exact reconstruction of a tensor from a correct base [19], but extending the proof through a native loader requires conditions on the loader’s transformations and storage writes. In verl, NaN masks in intercepted copies protect unchanged positions, and a round-trip test checks that the model’s generated outputs are bit-identical [36], but the loader’s supported transformations are not stated. SparseRL-Sync patches the loader’s copy with a NaN-masked sparse scatter and reports tensor-by-tensor bitwise agreement with a dense refit, but does not specify supported transformations or interception of every storage write [11]. NeMo-DCR specifies both in the loader conditions of § 6.1 and Appendix A.2, and Appendix A proves that under these conditions its refits produce the same bits as a dense refit.

In approach C, arithmetic reconstruction of updated or pre-update values can introduce rounding errors. ROSE sends arithmetic differences [6]. AuroraRL reports lossless reconstruction by scatter-adding deltas but does not state when this reconstruction is bit-exact [30]. AReaL-DTE [26] reconstructs pre-update weights by inverting AdamW and compares BF16 bit patterns after aligning them to a common layout. Its authors note rounding in fused AdamW implementations, so comparison against these reconstructed pre-update weights can miss a changed element. NeMo-DCR instead compares against stored values retained in the committed source baseline.

Approaches A and B move every weight byte, while the delta schemes in approaches C and D scale with the changed set. PULSE, SparseRL-Sync, and verl in approach D send absolute overwrites as indices and values of changed elements, with BF16 values in PULSE and verl. The verl framework detects changes on each training rank’s shard and maps them to full-tensor coordinates through block placements, and it supports conversions only when they permute elements [35, 36]. AReaL-DTE sends target values of detected changes, and AuroraRL packages each step as a BF16 delta checkpoint.

The serving runtime performs all weight placement in checkpoint-engine, SparseRL-Sync, and verl, and only part of it in NCCL-Reshard and TensorHub. In checkpoint-engine, the serving runtime also chooses which weights to copy. NCCL-Reshard copies expert feed-forward shards directly into vLLM parameters using its own placement metadata and hooks. Only the remaining parameters pass through the native loader, so native placement is partial. TensorHub copies its published buffers into the serving runtime’s registered tensors without interpreting their layout. Yet weights are converted to the rollout layout before publication, not by the native loader, so native placement is only partial [40].

Most delta systems place updates themselves. ROSE uses shard-aware routing to receiver shards, and AuroraRL writes directly into parameter storage. PULSE writes values at the transmitted indices into receiver tensors that share the sender’s layout. AReaL-DTE remaps updates into rollout layouts at the receiver and uses the native loader only as a fallback, so its native placement is partial.

NCCL-Reshard, SparseRL-Sync, and verl each use a collective that spans training and rollout. The checkpoint-engine system runs alongside serving runtimes, loads full weights onto GPUs from disk or the training engine, and broadcasts them among its workers. Its description mentions no cross-cluster transport [20]. PULSE, AReaL-DTE, ROSE, AuroraRL, and TensorHub transfer weights through replication, relays, or shared storage without a cross-cluster collective. TensorHub pipelines its full-weight replication, placing one replica in each remote datacenter before replicating locally. AuroraRL streams each delta checkpoint through one seed actor per region.

No existing system in Table 1 fully meets G5. ROSE, SparseRL-Sync, and verl describe no recovery protocol, although verl does checksum each broadcast payload. For NCCL-Reshard and checkpoint-engine, repeating a dense refit can restore weights, but the cited descriptions do not specify a complete protocol for partial failures and policy commit. TensorHub provides transactions, invalidates incomplete replicas, and recovers transfers from another source [40], but it coordinates version selection within each model-parallel group rather than committing across all required receivers. AReaL-DTE commits a version manifest and leaves partially applied versions to its control plane, without describing their repair. AuroraRL checks the version a delta applies to, uses leases for fault handling, stages deltas before activation, and lets lagging actors replay the delta chain, but does not describe repair after partial writes.

PULSE receivers advance independently, without committing the source baseline and the required receivers’ policy version together. PULSE’s Algorithm 5 checks the local version before decoding [19], and a receiver applies consecutive deltas directly. PULSE also keeps periodic full checkpoints called anchors. After missed versions, the receiver restores a ready anchor and replays subsequent deltas in order. Ready markers prevent use of incomplete uploads, and a full-state hash checks each reconstruction before the new weights are returned. A mismatch triggers anchor recovery. Absolute overwrites can be repeated safely, and anchor restoration replaces a partially applied state.

The slime framework’s delta weight sync publishes byte-level XOR or overwrite deltas of the gathered Hugging Face tensors to a shared filesystem [33]. Each rollout node patches a full local checkpoint, verifies per-tensor checksums, and reloads the checkpoint from disk through the native loader. This design meets G1–G4, but every refit reads the full model. It does not fully meet G5: the trainer advances its source baseline before any rollout node applies the published version, and no commit ties the baseline to the version that the rollout nodes hold.

November 7 as Victims of Communism Day - 2026

📅 2026-11-07  |  Read Source →

Mostly law professors | Sometimes contrarian | Often libertarian | Always independent

I have long advocated using May 1 for this purpose. But November 7 is a worthy alternative candidate, which I am happy to adopt if it can attract a broad consensus.

NOTE: The following post is largely adapted from last year's November 7 post on the same subject.

Since 2007, I have advocated designating May 1 as an international Victims of Communism Day. The May 1 date was not my original idea. But I have probably devoted more time and effort to it than any other commentator. In my view, May 1 is the best possible date for this purpose because it is the day that communists themselves used to celebrate their ideology, and because it is associated with communism as a global phenomenon, not with any particular communist regime. However, I have also long recognized that it might make sense to adapt another date for Victims of Communism Day, if it turns out that some other date can attract a broader consensus behind it. The best should not be the enemy of the good.

As detailed in my May 1 post from 2019, November 7 is probably the best such alternative, and over time it has begun to attract considerable support. Unlike May 1, this choice is unlikely to be contested by trade unionists and other devotees of the pre-Communist May 1 holiday. While I remain unpersuaded by their objections on substantive grounds, pragmatic considerations suggest that an alternative date is worth considering, if it can  thereby attract broader support.

The November 7 option is not without its own downsides. From an American standpoint, one obvious one is that it will often fall close to election day. On such occasions, a November 7 Victims of Communism Day might not attract as much attention as it deserves, because many will - understandably - be focused on electoral politics instead. Nonetheless, November 7 remains the best available alternative to May 1; or at least the best I am aware of.

For that reason, I am once again  doing a Victims of Communism Day post on November 7, in addition to the one I do on May 1. If November 7 attracts more support, I may eventually switch to that date exclusively. But, for now, I reserve the options of returning to an exclusive focus on May 1, doing annual posts on both days, or switching to some third option should a good one arise.

In addition to its growing popularity, November 7 is a worthy alternative because it is the anniversary of the day that the very first communist regime was established in Russia. All subsequent communist regimes were at least in large part inspired by it, and based many of their institutions and policies on the Soviet model.

The Soviet Union did not have the highest death toll of any communist regime. That dubious distinction belongs to the People's Republic of China. North Korea probably surpassed the USSR in the sheer extent of totalitarian control over everyday life. Pol Pot's Cambodia may have surpassed it in terms of the degree of sadistic cruelty and torture practiced by the regime, though this is admittedly very difficult to measure. But all of these tyrannies - and more - were at least to a large extent variations on the Soviet original.

Having explained why November 7 is worthy of consideration as an alternative date, it only remains to remind readers of the more general case for having a Victims of Communism Day. The following is adopted from this year's May 1 Victims of Communism Day post, and some of its predecessors:

The Black Book of Communism estimates the total at 80 to 100 million dead, greater than that caused by all other twentieth century tyrannies combined. We appropriately have a Holocaust Memorial Day. It is equally appropriate to commemorate the victims of the twentieth century's other great totalitarian tyranny.

Our comparative neglect of communist crimes has serious costs. Victims of Communism Day can serve the dual purpose of appropriately commemorating the millions of victims, and diminishing the likelihood that such atrocities will recur. Just as Holocaust Memorial Day and other similar events promote awareness of the dangers of racism, anti-Semitism, and radical nationalism, so Victims of Communism Day can increase awareness of the dangers of left-wing forms of totalitarianism, and government domination of the economy and civil society.

While communism is most closely associated with Russia, where the first communist regime was established, it had comparably horrendous effects in other nations around the world. The highest death toll for a communist regime was not in Russia, but in China. Mao Zedong's Great Leap Forward was likely the biggest episode of mass murder in the entire history of the world.

November 7, 2017 was the 100th anniversary of the Bolshevik seizure of power in Russia, which led to the establishment of the first-ever communist regime. On that day, I put up a post outlining some of the lessons to be learned from a century of experience with communism.  The post explains why the lion's share of the horrors perpetrated by communist regimes were inherent flaws  of the system. For the most part, they cannot be ascribed to circumstantial factors, such as flawed individual leaders, peculiarities of Russian and Chinese culture, or the absence of democracy. Prosecution Over Threat to American Federation of Teachers President Randi Weingarten Can Go Forward

📅 2026-11-07  |  Read Source →

Mostly law professors | Sometimes contrarian | Often libertarian | Always independent

From U.S. v. Spitzer (N.D. Ga.), filed by Magistrate Judge John Larkins on Oct. 9, and just affirmed Wednesday by Judge Eleanor Ross:

The indictment alleges that on July 23, 2024, Mr. Spitzer posted the following message on the website for the American Federation of Teachers, a labor union, regarding its president ("Individual #1"):

[Individual #1] is an ignorant incompetent cunt that should be worried for her safety. Fact that she is still alive. Liberal nazi deserves the bullet to head. Resign before she ends like what happened to trump at his speech. They won't miss fat bitch.

The indictment alleges that the post violated 18 U.S.C. § 875(c), which makes it a federal crime to transmit in interstate commerce any communication containing a threat to injure another person.

Mr. Spitzer argues that assuming the allegations in the indictment were true, it fails to state an offense because the posting was not a "true threat," or even a threat at all, and thus is protected by the First Amendment. As he sees it, the posting was simply political speech about a public figure and did not advocate the use of force or violence against Individual #1.

{In an effort to contextualize the posting, Mr. Spitzer points to an internet article in which Mike Pompeo, the former U.S. Secretary of State, described Individual #1 as "the most dangerous person in the world"; examples of "conservative politicians and commentators" criticizing her approach to school closures during the pandemic; and examples of Individual #1's own political statements. But these are not facts that the Court can consider at this juncture because they fall outside the four corners of the indictment.}

The government responds that whether Mr. Spitzer's posting qualified as a true threat is a question for the jury and that a pretrial determination of the sufficiency of the evidence is procedurally improper. The government further asserts that Mr. Spitzer improperly relies on facts not alleged in the indictment to contextualize the posting. The government has the better argument….

Considering the allegations on the face of the indictment—as this Court must—the Court finds that a jury could conclude that Mr. Spitzer's alleged posting constituted a "true threat." There are at least four separate references to harming or killing Individual #1, including: that she should be "worried for her safety"; that she "deserves a bullet to [the] head"; that unless she resigns she risks being shot similar to the attempted assassination of President Donald J. Trump; and that she will not be missed. In addition, the posting makes an oblique reference to her still being alive, which when combined with the other statements, can reasonably be interpreted as evidencing a present intent to intimidate and place Individual #1 in fear of bodily harm or death. The screed's liberal use of epithets further tends to show that the posting was not simply on a matter of public concern, but rather a threat against Individual #1 personally….

In his reply, Mr. Spitzer relies on the Supreme Court's decision in Watts v. United States, to argue that "political hyperbole" is not a "true threat." True enough, but Watts is distinguishable. In that case, the Supreme Court overturned the conviction of Watts, an 18-year-old Black protester who was charged with threatening President Lyndon B. Johnson during a political rally at the Washington Monument during the 1960's. During the protest, Watts said:

They always holler at us to get an education. And now I have already received my draft classification as 1-A and I have got to report for my physical this Monday coming. I am not going. If they ever make me carry a rifle the first man I want to get in my sights is L.B.J. They are not going to make me kill my black brothers.

The Supreme Court held that considering the full context of the statement—including that it was conditional upon Watt's joining the military (which he said he would not do) and that the listeners laughed at his statement—it was "political hyperbole," not a true threat. In contrast, Mr. Spitzer's alleged statement is much more threatening for the reasons explained above. Also, significantly, Watts was decided after trial, based on a developed evidentiary record, which underscores why dismissal at this juncture is not appropriate.

Accordingly, dismissal of the indictment is not warranted. But, of course, Mr. Spitzer is free to renew his challenge to the sufficiency of the evidence at trial….

Going the Extra Mile: Jeff Xu helps dozens of New Yorkers with end-of-life needs

📅 2026-11-07  |  Read Source →

For nearly a decade, Jeff Xu has helped low-income New Yorkers who are 60 and older with their wills and other life planning documents through the Volunteers of Legal Service Senior Law Project.

During the COVID-19 pandemic, Xu began meeting with clients over Zoom to execute these documents. He also led execution ceremonies wherever clients felt comfortable—in coffee shops, restaurants or even their homes.

For one client, Xu went all the way to Staten Island, which even as a New York City native was his first trip to its southernmost borough, he says.

“During COVID and even now, there are clients who are unable to travel, and VOLS often steers them my way because they know that I’m willing to do these types of home visits,” says Xu, a partner in the finance group at Morrison Foerster.

Abja Midha, the executive director of Volunteers of Legal Service, notes that the nonprofit organization’s staff often conducts home visits for senior clients who can’t come to the office because of physical disabilities or various medical needs. But it is far less common for pro bono attorneys to pay those calls.

“It really shows Jeff’s dedication to working with this population,” Midha says. “He will take time out of his day, traveling both ways, to meet clients in their homes to make sure they get their legal needs met. It’s truly commendable.”

Xu began handling pro bono matters for Volunteers of Legal Service when he joined Morrison Foerster as a first-year associate in 2016.

Born in Queens and raised on Long Island, Xu was surrounded by teachers and other mentors who impressed upon him the importance of community service. In high school, he volunteered at a hospital.

Later, while at Johns Hopkins University, he tutored inmates at Baltimore’s city jail.

“It was sold to me as you have to understand your privilege and your fortunate position,” says Xu, a graduate of Fordham University School of Law. “You can’t take all that for granted, and you need to pay it forward.”

As a young attorney, Xu appreciated that his firm not only encouraged but expected pro bono service. As he developed his transactional practice, he gravitated toward the Volunteers of Legal Service Senior Law Project.

He found wills, powers of attorney and advance medical directives are much like the contracts he deals with as a finance lawyer in that they must be entirely unambiguous, he says.

“There is a need for any court to look at these documents in the future and say, ‘This is exactly what’s intended. It’s totally clear. There’s no room for debate,’” Xu says. “That parallels nicely with my day-to-day.”

Xu has since helped dozens of clients finalize their wishes for end-of-life care and the disposition of their assets. As part of the process, he arranges initial meetings with clients in person, over the phone or remotely. After preparing their documents, he meets with them again for the execution ceremony.

Xu says he often needs to be flexible and creative. During home visits, he asks clients to enlist their friends and neighbors as witnesses. He also finds ways to communicate with clients who may not have reliable access to a phone or email.

In one instance during the pandemic, Xu received a card from a woman that included $60. Even though he returned the money, he felt like he made a real difference by settling her affairs and relieving her worries.

“Frankly, that’s why I keep doing this,” Xu says. “As people are approaching the end of their life, a lot of them don’t have the means to pay for an attorney, and they’re intimidated by what it takes to do it yourself. They’re stuck in this weird spot where they just don’t do anything.”

Jennifer Brown, supervising counsel of pro bono at Morrison Foerster, describes Xu as a “very willing volunteer.” By her last count, he had provided more than 750 hours of pro bono service.

Because of his relationship with Volunteers of Legal Service, the nonprofit once asked Xu to assist with a training for Morrison Foerster attorneys, Brown recalls.

It was an unusual request, and what Xu told his colleagues was striking, she adds.

“He said it might be scary, the idea of talking to people about these issues, because they’re very personal, and they can call up a lot for people,” Brown says. “He was so sensitive, and it was clear that he doesn’t see these matters as, you know, ‘We’ll just fill out this collection of forms for someone.’”

After Xu was promoted to partner last year, he took a more active role in recruiting and training other lawyers at Morrison Foerster to represent clients through the Volunteers of Legal Service Senior Law Project.

While Xu handles three or four of his own matters annually, he oversees attorneys in his group and in other groups at the firm who are handling countless more, he says.

“That’s the number that’s really more important, because I am able to encourage other attorneys to get involved with this, and then hopefully that multiplies in a way that is positive,” Xu says.

Xu expanded his work with Volunteers of Legal Service in other ways, including by organizing execution clinics at the firm so multiple clients can finalize their life planning documents at one time. He also joined its board of directors and is working more on fundraising.

“Those types of things are where my mind is at, in terms of what I’m trying to do pro bono-wise,” says Xu, who received the New York State Bar Association’s President’s Pro Bono Service Award for the First Judicial District for his work in May. “Those are the things I will continue to do.”

Apart from his focus on pro bono, Xu, whose parents emigrated from China, encourages diversity, equity and inclusion initiatives in his firm. He lives on Long Island with his wife and 3-year-old daughter, with whom he spends the rest of his time.

“But before I had a 3-year-old, and during the pandemic, I got really into baking bread,” adds Xu, who often gifted loaves to colleagues and clients. “It got to the point where my wife was like, ‘You have to slow this down.’”

A Hidden Substance in Drinking Water May Be Linked to Heart Problems in Children

📅 2026-11-07  |  Read Source →

The water we drink may hold clues to a rare heart condition in children, but whether naturally occurring lithium plays a role in its development remains unknown.

A dangerously fast heartbeat can begin with an extra strand of heart muscle that forms before birth. The strand creates an abnormal electrical connection, allowing the heart’s rhythm to go awry. Doctors can eliminate these connections, but a larger question has remained largely unanswered. Why do they develop in the first place?

A study led by UC San Francisco researchers points to a possible environmental clue in drinking water. Children living in areas with higher levels of naturally occurring lithium were more likely to be diagnosed with Wolff-Parkinson-White syndrome, or WPW, a rare condition involving a particular type of abnormal connection. The findings, published online in The Journal of Clinical Investigation, show an association, but do not establish that lithium causes the condition.

These connections, known as accessory pathways, usually occur in people with no family history of the condition. That suggests environmental exposures during fetal development could play a role. Lithium attracted the researchers’ attention because medicinal doses taken during pregnancy have been associated with an increased risk of congenital heart defects, including Ebstein’s anomaly. This rare defect is frequently accompanied by accessory pathways, prompting the team to investigate whether lithium in drinking water might also be associated with changes in the developing heart.

The researchers analyzed health and water-quality data for more than 2.3 million children in California. Just 686 had a documented WPW diagnosis. Children living in counties with lithium levels in the highest 25% had 71% greater odds of a diagnosis than those in counties with lower levels.

The team then tested its main finding among nearly 2 million children in New York. There, children living in areas with lithium levels above 10 parts per billion also had greater odds of a WPW diagnosis.

Higher lithium levels in California were also associated with palpitations, fainting, and supraventricular tachycardia, or SVT, a rapid heart rhythm that can cause palpitations and other symptoms. Accessory pathways are among the most common causes of SVT. WPW is also associated with a small increased risk of sudden death. Doctors can treat accessory pathways with catheter ablation, a minimally invasive procedure that eliminates the small area of heart tissue responsible for the abnormal electrical connection.

“We’ve known about these pathways for decades, and we know how to treat them, but we haven’t known why people develop them,” said Gregory Marcus, MD, MAS, an endowed professor in atrial fibrillation research in the UCSF Division of Cardiology and senior author of the study. “This is an exciting step because it points to a potential environmental factor that may be modifiable. But we need more research to determine whether lithium is actually contributing to their development.”

The study estimated exposure from the county of residence. Researchers did not know how much lithium individual children or their mothers consumed, and other environmental or genetic factors could help explain the association. Studies in other populations and research that measures exposure during pregnancy more precisely are needed to determine whether lithium plays a causal role.

Marcus said the findings should not alarm people about the safety of their drinking water, including those who are pregnant. Despite the association, WPW was rare in the children studied.

Lithium occurs naturally in groundwater, and its concentration varies widely by location. Groundwater used for drinking water across the United States and elsewhere contains lithium, raising questions about the findings’ potential public health significance beyond California and New York. The researchers said the results underscore the value of collecting environmental data to understand how ordinary exposures may affect health.

“We’re exposed to things in our environment every day, including substances that occur naturally,” Marcus said. “The more precisely we can measure those exposures and connect them with health outcomes, the better we can understand what may be influencing health.”

Lithium in drinking water is not currently regulated in the United States, although the U.S. Environmental Protection Agency requires monitoring through its program for unregulated contaminants. The U.S. Geological Survey also measures lithium in groundwater.

“The next step is to determine whether lithium itself is contributing to the development of these pathways and, if so, how much exposure matters and when during development it matters most,” Marcus said. “That will require studies that can measure exposure much more precisely.”

Dewland and Gregory M. Marcus, 13 October 2026, The Journal of Clinical Investigation. DOI: 10.1172/JCI205020

Scientists Find That Older Brains React Very Differently to a Night of Poor Sleep

📅 2026-11-07  |  Read Source →

A single bad night’s sleep may be easier on a healthy older brain than a younger one, though regularly missing sleep still carries risks.

Sleep quality often declines with age, yet older adults can seem less affected by a single bad night than younger people. Understanding that apparent mismatch means looking at how the brain responds when sleep runs short.

A study from Simon Fraser University offers a possible explanation. After just three hours of sleep, certain connections in younger and older brains changed in opposite directions. The findings suggest that healthy older brains may adapt to acute sleep loss in ways that help preserve function, although the study measured brain activity rather than cognitive performance.

The research, published in Imaging Neuroscience, compared brain networks in younger adults ages 20 to 30 with those in older adults ages 65 to 75. Lead researcher Josh Neudorf, an affiliate member of SFU’s Institute for Neuroscience and Neurotechnology, says earlier research on the effects of poor sleep provided a reason to investigate the difference.

“Older adults tend to better handle the effects of poor sleep, whereas younger adults, as we know, have the common symptoms of decreased mood and cognitive ability following poor sleep,” says Neudorf.

“This study tries to get at the heart of this difference – how does the older brain react to lost sleep.”

Brain connectivity describes how activity in different regions is linked. Stronger connections do not automatically mean the brain is working more efficiently. The arrangement matters, too. In a more modular network, regions are organized into groups, with relatively stronger connections within each group than between groups.

“What we found was quite striking in that older and younger brains actually responded in opposite ways to acute sleep loss.

“Certain connections in the brains of younger adults showed increased connectivity as a response to less sleep, while those same connections in the brains of older adults showed decreased connectivity.

“That decrease in connectivity promotes more efficient modular connectivity for the brain as a whole. In other words, the brain is acting in a more efficient way to maintain cognitive function. In contrast, the increased connectivity in younger brains suggests the brain is having to work harder to maintain function.”

Whether those network changes actually helped the older participants think or perform tasks better was not tested. The proposed benefit is an interpretation of the brain activity, consistent with previous research suggesting that older adults are often less impaired by a single night of poor sleep.

The reason for the opposite responses also remains open. One of several possible explanations is compensation, in which an aging brain reorganizes its networks and uses different strategies to maintain function.

“The quality of sleep starts to change and deteriorates somewhat in older adults,” says Neudorf.

“The theory of compensation is the idea that older brains adapt or compensate for those changes.”

Being able to adjust to an occasional short night would not make regularly missing sleep harmless. Researchers emphasize that good-quality sleep matters throughout life. Although the response to one or two nights of lost sleep may differ with age, chronic sleep loss is detrimental to brain health and cognitive ability. Its cumulative effects over a lifetime also have the potential to increase the risk of cardiovascular disease, hypertension, diabetes, weight problems, and colorectal cancer.

Dementia presents another concern. Study co-author Brianne Kent is an assistant professor of psychology, associate director of SFU’s Institute for Neuroscience and Neurotechnology, and Canada Research Chair in Translational Neuroscience and Dementia. Her research focuses on Alzheimer’s disease, the most common cause of dementia.

“A lot of sleep disruption could increase your risk of dementia,” says Kent.

“What we know is that there’s a protein called amyloid beta, which accumulates in the brain and causes these plaques in the brains of individuals who have dementia. Amyloid beta is this toxic protein, a waste product of your brain. These plaques accumulate for, on average, about 20 years before dementia starts.”

Sleep plays a role in how quickly that protein is removed, linking repeated sleep loss to a process that can unfold over decades.

She concludes, “During sleep, that protein is cleared out at a faster rate. So if you’re continuously missing sleep, then that protein and those plaques will accumulate at a faster rate. Not everyone who has poor sleep will get Alzheimer’s disease, but if you are somebody who has the predisposition for the disease, then missing sleep over time will drive the process.”

Deep-Sea Scientists Capture Extraordinary 4K Footage of a Fish With a See-Through Head

📅 2026-11-07  |  Read Source →

MBARI’s first 4K footage of a barreleye fish offers a rare chance to study how its unusual eyes work in the ocean’s dim twilight zone.

The day’s deep-sea research was over when a fish with a transparent head came into view. Research Specialist Shannon Johnson spotted it as MBARI’s pilots were “flying” the remotely operated vehicle (ROV) Doc Ricketts back to the surface for recovery, and she called for them to stop.

The animal was a barreleye fish (Macropinna microstoma), approximately 600 meters (1,970 feet) underwater and 90 kilometers (55 miles) offshore. For the MBARI scientists working aboard the research vessel David Packard, this was only the organization’s eleventh encounter with the species.

Senior Scientist Steven Haddock and researchers from MBARI’s Biodiversity and Biooptics Team were on the eight-day Diving Deep for Delicate Drifters expedition, studying gelatinous animals such as jellies, siphonophores, and ctenophores, also known as comb jellies. They combined scuba diving in open water near the surface with ROV surveys hundreds of meters below, filming and collecting animals to better understand how they have adapted to life in the deep water column.

Most of the scientists had already moved to the ship’s wet lab to prepare to catalog the specimens arriving with the ROV. When news of the barreleye reached them, they ran back to the control room. The encounter was an unexpected finish to a long, productive week of research.

“Seeing a barreleye fish is a rare treat. Crew from across the ship joined the science team in the control room, mesmerized by this remarkable animal. Deep-sea animals capture the imagination, creating wonder and awe that we hope will inspire stewardship of the largest living space on Earth,” said Haddock.

The team spent approximately 20 minutes observing the fish with Doc Ricketts’ high-resolution 4K camera, examining its body and behavior and experimenting with different lighting conditions to show its transparent head shield. This was MBARI’s first barreleye sighting filmed in 4K and its first from the new flagship research vessel.

ROV Pilot/Technician Cameron Law also maneuvered Doc Ricketts close enough to record the fish with the vehicle’s virtual reality (VR) camera. The resulting 3D stereo imagery could contribute to future education and outreach efforts.

MBARI has completed roughly 7,000 ROV dives and recorded more than 41,000 hours of deep-sea video during nearly 40 years of ocean exploration. Its previous sighting of Macropinna was in 2021. This summer, MBARI researchers leading an expedition with Schmidt Ocean Institute in the mid-Atlantic Ocean recorded another species of barreleye, the binocular fish (Winteria telescopa).

Earlier MBARI observations by Senior Scientist Bruce Robison and Research Specialist Kim Reisenbichler helped reveal how Macropinna uses its unusual eyes to feed. In the ocean’s dim twilight zone, the fish’s large fins keep it stable and allow it to maneuver as it hovers, looking upward for the silhouettes of prey. Once it spots food, its large, tubular eyes rotate beneath the transparent dome to keep the target in view. A Healthier Form of Salt Could Prevent Nearly 3 Million Deaths Every Year, Scientists Say

📅 2026-11-07  |  Read Source →

A global study spanning 193 countries suggests that a simple change to everyday salt could prevent millions of deaths and cases of cardiovascular and kidney disease each year.

Replacing ordinary salt with a potassium-enriched alternative could prevent nearly three million deaths worldwide each year, according to a new study covering 193 countries. Researchers estimate that a global switch could also prevent more than ten million new cases of cardiovascular and kidney disease annually, offering a potentially powerful way to reduce the health burden of high blood pressure.

The analysis, led by The George Institute for Global Health, examined how different levels of salt replacement might affect the world’s 4.6 billion adults. The findings suggest that even limited changes, particularly among people already diagnosed with high blood pressure, could produce substantial health gains.

Potassium-enriched salt replaces part of the sodium chloride in regular table salt with potassium chloride. It looks, tastes, and performs much like conventional salt in cooking but contains less sodium and provides additional potassium, two changes that can help lower blood pressure.

“Consuming too much sodium and not enough potassium are well established causes of high blood pressure, a major risk factor for life-threatening conditions like strokes, heart attacks and kidney disease. Switching to potassium-enriched salt addresses both these dietary issues at the same time, with substantial health benefits,” said Bruce Neal, Senior Professorial Fellow at The George Institute.

High blood pressure (hypertension) affects approximately 1.4 billion adults aged 30 to 79 worldwide, or roughly one in three people in that age group. Cardiovascular disease (CVD) caused 19.2 million deaths in 2023, nearly 50 percent more than three decades earlier. In 2025, the World Health Organization (WHO) endorsed potassium-enriched salt as a way to reduce blood pressure and cardiovascular risk.

The researchers modeled several scenarios, including replacing all salt consumed at home, in restaurants, and in processed foods. Switching only household table salt could prevent approximately 1.85 million deaths and 6.19 million new cases of cardiovascular and chronic kidney disease annually. Replacing salt exclusively in processed and restaurant foods could prevent another estimated 1.56 million deaths and 5.46 million new disease cases each year under that separate scenario.

More targeted approaches also showed considerable potential. If 80 percent of people with diagnosed hypertension switched their household salt, the model projected approximately 590,000 fewer deaths annually. Among those receiving treatment for hypertension, a comparable level of adoption could prevent about 480,000 deaths each year.

“While a global shift from regular salt to a potassium-enriched substitute is aspirational, this is a starting point to get countries thinking about the opportunity, with much greater potential and at much lower cost than many drug-based treatments,” Neal said.

The projected benefits varied considerably between countries. Under a complete replacement scenario, China could prevent approximately 1.08 million deaths and 3.61 million new cardiovascular and kidney disease cases annually. India could avert nearly 400,000 deaths and 1.53 million new cases, while the United States could prevent approximately 105,000 deaths and 492,000 new cases.

Achieving these reductions would require strategies tailored to how people consume salt. In many countries, household cooking accounts for a substantial share of sodium intake. In Europe and North America, however, processed and restaurant foods contribute more than 70 percent, making cooperation from food manufacturers and restaurants essential.

“To realize the maximum benefits from switching to potassium-enriched salt, we need to see the food industry in Europe and North America, where over 70% of salt intake comes from processed and restaurant foods, get on board. This would also require investigating ways to scale up the production of potassium chloride to meet demand,” Neal said.

Although potassium-enriched salt can help lower blood pressure, it may pose risks for people whose kidneys cannot effectively remove excess potassium from the bloodstream. This can lead to hyperkalemia, a potentially dangerous condition that can disrupt the heart’s electrical activity. People with advanced kidney disease and those taking certain medications that increase blood potassium levels require particular caution.

The study’s modeling suggested that the overall health benefits could outweigh the risks even among people with advanced kidney disease. However, that population-level finding does not mean potassium-enriched salt is safe for every individual.

“People with serious kidney disease and those taking medications that significantly raise blood potassium levels need to take precautions. Risks for this group can be managed effectively through patient education, product labeling, and clinical oversight,” said Professor Vivek Jha, a nephrologist and Senior Professorial Fellow at The George Institute in India.

President Donald Trump said he has ordered the Department of Justice to open an investigation into instances of Democratic lawmakers "threatening" to impeach Attorney General Todd Blanche, among others.

The announcement, which was made via a Truth Social post Saturday afternoon, came after the Democrats retook control of the House and Senate in the midterm elections, winning strong majorities in both chambers of Congress.

"The Democrats are going around threatening a lot of people, including the Attorney General of the United States, and others, with Impeachment and many other forms of punishment, even though they admit they have no reason to do so," Trump wrote.

Since Election Day, two House Democrats — Reps. Hank Johnson, D-Ga., and Deborah Ross, D-N.C. — have publicly said they would support impeaching Blanche.

"I personally believe that the offenses of Todd Blanche demand that he be impeached and convicted and removed from office," Johnson said Thursday in an interview on SiriusXM’s "The Dan Abrams Show."

Ross went on host Dan Abrams' radio show shortly after Johnson and said she supported impeaching Blanche as well, but thought Democrats "should start with Hegseth."

In his post, Trump denied that any "impeachable acts" had been committed by Blanche or any other administration officials. He didn't mention Johnson or Ross by name, nor did he mention the fact that Thomas Massie, R-Ky., will likely reintroduce impeachment articles against Secretary of War Pete Hegseth on Monday.

Trump named only one Democratic politician, Sen. Elissa Slotkin of Michigan, in his post. He accused her of saying she would "go after all young people that believe in Republican Values."

I want them to be like, 'Lord, that might be buying myself a ton of problems that I don't want, and so let me avoid participating in that,'" Slotkin said. "I want that deterrence message sent."

Trump also said that Democrats have been threatening Republican donors "with imprisonment" because of their views.

Trump concluded his post by saying "these EXTORTIONISTS" should be imprisoned and that he wanted the DOJ to investigate the alleged actions as a "criminal act."

Trump wore a Dalma suede bomber jacket by Nour Hammour, paired with an Adam Lippes skirt and Manolo Blahnik BB pumps for the occasion, blending her signature polished style with a more relaxed look suited to a college football weekend.

The first lady's visit unfolded against a distinctly LSU backdrop, with purple-and-gold tailgating crowds lining the motorcade route and a massive American flag hanging above the stage inside Patrick F. Taylor Hall.

LSU cheerleaders flanked Trump during her remarks, and the Tiger mascot presented her with both scholarship checks while wearing a signature "Be Best" T-shirt.

Ousted Paraguayan president appears before prosecutors

📅 2026-11-07  |  Read Source →

Paraguay's President Santiago Peña waves after a meeting with Venezuela's interim President Delcy Rodriguez at the Miraflores Presidential Palace in Caracas, on September 19, 2026. Federico Parra/AFP via Getty Images hide caption

Paraguayan President Santiago Peña was impeached and placed under house arrest Friday after the collapse of a prominent U.S.-owned bank with ties to Paraguay's government. The fallout has left millions across the country without access to their money.

Peña is one of Washington's closest allies in the region and was a shareholder in Ueno Bank, a digital lender that served about 3 million customers — more than half of the country's adult population.

He was known as a pro-market leader focused on making it easier to do business in the country, but legislators said he jeopardized state assets and benefitted himself through his connection to the bank.

Ueno Bank previously said more than a million people opened bank accounts for the first time using its services, which included generous cash back offers on groceries.

A trial has proceeded against Peña, and he appeared before prosecutors Saturday morning. The last president ousted from office was Fernando Lugo in 2012.

Peña has denied any wrongdoing but on Thursday he announced his resignation. Lawmakers refused to accept that resignation, and instead moved forward with the country's impeachment process.

At proceedings inside the country's Senate Friday, legislators unanimously found Peña guilty of malfeasance in office, according to the Senate's website.

Prosecutors then accused him of a breach of trust, among other charges, before placing him under house arrest.

"I want to apologize to the Paraguayan people if I have failed you," Peña said in a speech posted to social media.

Demonstrators burn an image depicting Paraguay's President Santiago Pena, during a protest over the banking crisis and his resignation, at the main square in the surroundings of the National Congress in Asuncion, on November 5, 2026. Daniel Duarte/AFP via Getty Images hide caption

Pedro Alliana, the country's vice president, was sworn in as president to serve out the rest of Peña's term until August 2028. In a speech on Friday, he announced he would take action to compensate people whose money was lost in the bank's collapse.

Paraguay's central bank said it seized control of Ueno Bank on Tuesday because its solvency ratio, an assessment of a company's long-term financial viability, no longer met legal standards.

Protests erupted across Asunción, the country's capital city, following the seizure.
